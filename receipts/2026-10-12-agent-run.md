## Caveats on the two checks that were only partly green

- **Step 12.** The button reached the processor's hosted page. No test donation
  was made: the operator had no processor sandbox account, which is the open
  decision [#5](https://github.com/lentago/monarda/issues/5) already carried and
  [#17](https://github.com/lentago/monarda/issues/17) proposes to settle with
  per-processor presets and sandbox walkthroughs.
- **Step 13.** The contact section rendered its `mailto:` link with the right
  address and subject. Opening a mail client is not something a headless
  operator can confirm; a human run should click it.

## What the drill found

- **The first run is red on every new repo.** The template's initial commit
  triggers `deploy-pages.yml` before Pages is enabled (step 7), and
  `configure-pages` fails with "Get Pages site failed." The next run, after step
  7, was green. Filed as [#19](https://github.com/lentago/monarda/issues/19).
- **`npm run a11y` fails against the live site as written.** The config pins
  `http://127.0.0.1:4321/` and a URL on the command line is added, not
  substituted, so the live page passed and the command still exited 2. Filed as
  [#20](https://github.com/lentago/monarda/issues/20).
- **Dependabot runs on day one.** The template ships `dependabot.yml`, so the
  new repo had a Dependabot run in its Actions tab within a minute of creation.
  Harmless, worth one sentence in the README so it is not a surprise.
- **The "about an hour" estimate in `ADOPTION.md` is for a human first-timer.**
  This run is the floor, not the typical: an operator with the intake ready and
  the tooling installed. The honest first-timer number is still unrecorded; the
  next receipt should come from a human running it cold.
